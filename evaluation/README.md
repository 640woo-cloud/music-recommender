## 재실행

저장소 루트에서 Python과 pandas를 설치한 환경으로 실행합니다.

```bash
python evaluation/run_evaluation.py --content-zip /path/to/content_based_result.zip
```

스크립트는 main에서 제공한 `outputs/train.csv`, `outputs/test.csv`, `outputs/recs_popular.csv`, 기존 memory-cf 커밋의 추천 파일과 사용자가 지정한 로컬 ZIP을 읽습니다. 모델을 다시 학습하지 않고 저장된 추천 결과를 공통 `evaluate.py`로 평가하며, 결과를 `results/recomputed_metrics.csv`에 저장합니다. memory-cf 커밋이 없다면 먼저 `git fetch origin`으로 팀 브랜치를 가져옵니다.

## 평가 방법

학습 데이터 224,925행, 평가 데이터 56,727행, 사용자 973명, 아티스트 4,824명을 사용했습니다. 사용자별 청취 아티스트를 무작위로 약 80 대 20으로 분리했으며, 학습에서 이미 들은 아티스트를 제외하고 사용자당 10명을 추천했습니다.

Precision@10은 추천 10명 중 test와 일치한 비율, Recall@10은 해당 사용자의 test 아티스트 중 맞힌 비율입니다. 각 사용자에서 계산한 값을 973명에 대해 산술평균했습니다. 사용자마다 test 크기가 달라 두 지표의 순위가 달라질 수 있습니다.

## 주요 결과

| 방식 및 설정 | Precision@10 | Recall@10 |
|---|---|---|
| 인기도 기준선 | 29.53% | 5.46% |
| 협업 필터링 전체 이웃 | 46.43% | 10.02% |
| 협업 필터링 이웃 50명 | 52.15% | 11.35% |
| 콘텐츠 cosine 기본 | 6.44% | 1.34% |
| 콘텐츠 cosine_learned 기본 | 6.64% | 1.27% |
| 콘텐츠 KNN 기본 이웃 10명 | 4.46% | 0.98% |

협업 필터링 이웃 50명은 추천 10명 중 평균 약 5.21명이 test와 일치했습니다. 인기도 기준선은 학습 데이터에서 청취 사용자 수가 많은 아티스트를 우선 추천한 결과입니다. 콘텐츠 기본 설정은 청취 가중치 log, 특성 표준화, KNN 이웃 10명입니다.

# 콘텐츠 기반 설정별 평가

ZIP의 9개 CSV를 cosine, cosine_learned, knn으로 나눠 총 27개 조합을 평가했습니다. k3·k5·k20·k50 파일의 두 cosine 방식은 base와 동일하므로, 서로 다른 조합은 19개입니다. 아래 표는 Precision@10이며 모든 Recall 값은 첨부 CSV에 있습니다.

| 설정 | cosine | learned | KNN |
|---|---|---|---|
| base | 6.44% | 6.64% | 4.46% |
| w_binary | 6.45% | 6.52% | 4.52% |
| w_plays | 6.30% | 6.45% | 4.07% |
| s_none | 4.08% | 4.07% | 4.08% |
| s_log | 6.57% | 6.72% | 4.33% |
| k3 | 동일 | 동일 | 2.98% |
| k5 | 동일 | 동일 | 3.63% |
| k20 | 동일 | 동일 | 5.29% |
| k50 | 동일 | 동일 | 5.46% |

w_binary는 청취 여부, w_plays는 원본 재생 횟수를 가중치로 사용합니다. s_none은 표준화를 생략하고, s_log는 네 음악 특성에 log1p를 적용한 뒤 표준화합니다. k 설정은 KNN 이웃 수만 바꾸며 최종 추천 수는 항상 10명입니다.

## 관찰한 차이

전체 전달본 중 최고 Precision은 s_log + cosine_learned의 6.72%이고, 최고 Recall은 기본 cosine의 1.34%입니다. KNN은 이웃을 3명에서 50명으로 늘릴수록 성능이 좋아졌지만, 기본 cosine보다 낮았습니다. 표준화를 생략한 설정은 세 방식 모두 Precision 약 4.1%였습니다.

협업 필터링의 이웃 50명은 train 내부 검증에서 선택한 설정입니다. 콘텐츠 설정표는 test에서 관찰한 결과이므로 최고값을 독립적으로 검증된 최적 성능이라고 표현하지 않습니다. learned 코드의 내부 holdout은 특성 가중치 학습에 사용되며, 별도의 설정 선택 검증과는 역할이 다릅니다.

# 결과 해석과 공유 범위

## 성능 차이에 대한 해석

콘텐츠 기반은 아티스트별 평균 음악 특성 9개를 사용합니다. 곡별 스타일 차이와 사용자가 좋아한 특정 곡의 정보가 평균에 압축되며, 언어·문화·인지도 등은 직접 반영되지 않습니다. 반면 협업 필터링은 실제 청취 패턴을 활용합니다. 이러한 차이는 성능 격차에 대한 가능한 설명이며, 원인별 영향을 분리해 검증한 결과는 아닙니다.

test에 없는 새로운 아티스트를 추천하더라도 이번 지표에서는 적중으로 인정되지 않습니다. 따라서 점수는 실제 만족도 전체가 아니라 숨긴 청취 이력의 복원 정도를 나타냅니다. 무작위 분할이므로 미래 시점의 취향 예측 성능으로 일반화하지 않습니다.

## 검증한 사항

학습·평가 사용자–아티스트 쌍의 중복, 추천 목록의 중복, 기존 청취 아티스트 재추천, 후보 범위 및 추천 순위를 확인했습니다. 모든 전달본의 각 방식은 973명에게 10명씩 추천했습니다. 팀 공통 평가 함수와 별도 사용자별 계산 결과도 일치했습니다.

협업 필터링 기본 및 이웃 50명 결과는 원본 코드 재실행과 정확히 일치했습니다. 콘텐츠 기본 cosine은 재생성 시 작은 수치·동점 순위 차이로 9명의 추천 집합이 달랐고, Precision 차이는 약 0.0103퍼센트포인트였습니다. 본 표는 전달받은 파일을 기준으로 유지했습니다. 나머지 콘텐츠 방식은 전달본을 평가했습니다.
